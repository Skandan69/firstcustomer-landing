Why FirstCustomer exists

Prospecting breaks when discovery, analysis, outreach and follow-up live in different places.

FirstCustomer brings those steps into one workflow so a lead is not just a name in a list. Each prospect can carry the reason to contact them, website evidence, a demo, a proposal, the next action and the final outcome.

🔎
Discovery without relevance wastes time
Target a location and category, keep provider failures explicit, and prefer zero relevant results over unrelated businesses.
🧠
A lead needs a reason
Opportunity Intelligence explains why a business may be worth contacting and recommends the next service conversation.
🌐
Generic outreach is easy to ignore
Audit an existing site or generate a shareable concept website so outreach can reference something concrete.
📄
Interest needs a commercial next step
Build a structured proposal with editable scope, pricing, deposit, timeline, terms and a prospect-facing share link.
💼
Follow-up disappears without a pipeline
Move saved businesses through New, Contacted, Interested, Demo, Proposal, Won or Lost and keep the next action visible.
🔐
Provider keys belong on the server
Paid provider credentials stay behind server routes; public demo and proposal pages receive only sanitized structured data.

How the current product works

Core workspace access currently uses an anonymous workspace ID stored in your browser. You do not need to create a FirstCustomer login to use the current workflow.
Local Business Finder persistence, CRM activity, demos and proposals are stored server-side in Supabase under your anonymous workspace ID. Some older tools in the suite still use browser localStorage.
Paid provider credentials used by the stabilized tool suite are read server-side. The Provider Status screen returns configuration booleans, not credential values.
